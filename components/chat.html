Chat

The shell for a chatbot or assistant: a header, a scrolling conversation, suggested prompts and a composer. It has no backend; your code answers an event.

04 — Usage

Use it for

  • An assistant that answers questions about the person’s own content.
  • Two or three suggested prompts that show what it can do.
  • A note that answers can be wrong.

Avoid

  • Pretending a person is answering.
  • Long-form writing. Answers should be short and link onward.

05 — Accessibility

Notes

  • The conversation is a role="log", so new replies are announced.
  • The composer has a visually hidden label; the send button has an aria-label.

06 — Without Jewel’s JS

What the script does

The script adds each message to the log, shows a typing indicator, clears the composer and fires jewel:chatsend for your code to answer. The CSS reads only the markup below, so a framework can render the conversation from its own state and leave out chat.js and data-component.

Events and keyboard

  • Enter sends and Shift+Enter is a new line. Skip this during IME composition (isComposing) and on touch screens (pointer: coarse), where Enter is always a new line.
  • After each message, scroll the log to the bottom, smoothly unless reduced motion is on.
  • Clear the composer after sending. The textarea grows with field-sizing: content; where that isn’t supported, the script sets its height from scrollHeight as people type.
  • jewel:chatsend doesn’t fire without the script. Send the text to your backend yourself.
